# 05 只读检索 MCP 服务

`rag_readonly.py` 是一个 MCP 服务，将本地向量库的检索能力暴露给外部 Agent。文件为脱敏节选，已删除与本机专有服务绑定的部分，保留五条约束的实现。

| 约束 | 实现方式 |
|---|---|
| 只读 | 仅提供检索与取块，不提供写入、shell、任意命令或任意文件路径入参 |
| 库白名单 | collection 名单硬编码；真题库按正则匹配，未列入的库直接拒绝 |
| 防注入 | 子进程以列表形式传递 argv，并使用 `shell=False`，查询词作为单个参数传递 |
| 限额 | 查询 ≤ 500 字符，`top_k` ≤ 10，单块返回 ≤ 900 字符，子进程超时 120 秒 |
| 路径受限 | 正文工具仅返回库内字段；插图工具仅返回白名单目录内的绝对路径 |

## 部署形态

该进程运行在安装了 `mcp` 库的解释器中，实际检索交由向量库自身的 venv 子进程执行（`kb_search.py`、`kb_get_chunk.py`）。分为两个环境有具体原因：将 `chromadb` 与 `llama-index` 安装到主运行时会与其 `pydantic` 依赖冲突，导致主 Agent 的检索工具一并失效。

子进程启动前必须清除 `PYTHONPATH` 与 `PYTHONHOME`，否则会报 `ModuleNotFoundError: pydantic_core._pydantic_core`。该错误信息表现为库损坏，实际原因是环境变量污染。

## 工具描述的要求

工具描述需要明确排除「权限」解读：取不到表示库中没有对应内容，与权限无关。同时需要说明真题库的记录形态：按年份切分的判断题答案序列、名词解释列表，避免模型将其作为完整试卷输出。这两条来自实测；若不写入，模型会将答案序列作为题目输出。
